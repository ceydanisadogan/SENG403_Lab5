Part A · Measure (about 18 minutes)

A0Read the specification (3 minutes)

The JuiceBar sells juice in bottles. The function order_price(qty, size, member, coupon)JuiceBar.orderPrice(qty, size, member, coupon) returns the price of an order in TL. It uses the small function bottle_price(size)JuiceBar.bottlePrice(size).

#Rule
S1The quantity qty is a whole number from 1 to 20 bottles. If it is less than 1 or more than 20, the function raises ValueErrorIllegalArgumentException.
S2All bottles in one order have the same size. A small bottle ("S") costs 40 TL. A large bottle ("L") costs 60 TL. For any other size, the function raises ValueErrorIllegalArgumentException.
S3An order of 10 bottles or more gets 50 TL off.
S4If the customer has a coupon, the customer gets 10 % off. The 10 % is taken from the price after S3.
S5A member gets 15 TL off. This happens at the end, after S3 and S4.

Here is an example. A customer buys 12 small bottles. The customer has no coupon and is not a member. The price is 12 × 40 = 480. Then S3 takes 50 TL off: 480 − 50 = 430 TL.

A1Run the coverage tool and read the report (8 minutes)

Run this command in the folder that has the file juicebar.py:

pytest --cov=juicebar --cov-branch --cov-report=term-missing test_juicebar.py

Go to the java folder and run mvn -q test. Then open the file target/site/jacoco/index.html in your browser. To see the code in colours, click default, then JuiceBar, then the name of a method.

Copy the numbers from the report into the boxes below.

Now calculate the two coverage numbers yourself. The formulas are in section 3 of the cheatsheet.

Part B · Cover the missing branches (about 17 minutes)

B1Add tests until branch coverage is 100 % (17 minutes)

Do these steps for each line or branch that is still missing. First, find an input that goes there. Next, take the expected result from the specification (A0). Then write one test under YOUR TESTS. Run the coverage command again after each new test.

Your goal is Miss 0, BrPart 0 and Cover 100%.

In this step, use the command mvn -q test -Dmaven.test.failure.ignore=true. With this command, Maven writes the report even when a test is red. Your goal is no red lines, no yellow lines, and Missed Branches 0 of 14.

Is one of your new tests red? Then do these three things in this order:

1. Check your expected value against the specification again. Is the test wrong, or is the code wrong?

2. If the code is wrong, write the five-line defect report below.

3. Today you are also the developer. Correct the code so that it follows the specification. Change as little as you can. Run the tests again. Every test must be green.

Write a defect report in five lines. Use the format from lecture slide 27.

Part C · Mutation testing (about 20 minutes)

Check two things before you start Part C: all tests are green, and branch coverage is 100 %. The mutation tool stops if a test already fails on the original code.

C1Run the mutation tool and list the survivors (5 minutes)

Run python mutation_run.py. The tool prints one line for each mutant. Each line says killed or SURVIVED.

Run mvn -q test-compile org.pitest:pitest-maven:mutationCoverage. Near the end of the output, find the line >> Generated … mutations Killed … and read it. Then open target/pit-reports/index.html and click JuiceBar.java. A red line has a mutant that was not killed (SURVIVED or NO_COVERAGE). The list under the code shows each change.

List every mutant that survived. For each one, think about this question: which input makes the original code and the mutant give different results?

C2Kill the survivors (10 minutes)

Sometimes a mutant survives in a line that the tests run. There are two possible reasons. Reason 1: no test uses the input where the change makes a difference. Reason 2: a test uses that input, but it does not check the result. For each survivor, add a new test or make an old test stronger. Take every expected value from the specification.

Is a new test red on the original code? Then do the same three things as in B1. Check the specification, write down the defect below, and correct the code. Run the tests again. After that, run the mutation tool again.
